# UI Rules

仅当任务涉及页面结构、业务组件、表单、浮层、菜单、表格、导航或移动端交互时读取本文件。

## 组件复用

- 基础 UI 优先复用 `<shared-ui>`
- 不要在业务页面复制 `button`、`input`、`dialog`、`table`、`tabs`、`toast`、`tooltip`、`pagination` 等基础组件
- 业务域专属组件可以在目标项目内二次封装，但内部仍应消费 `<shared-ui>`
- 如果当前仓库仍保留本地 `src/components/ui` re-export，新增代码优先继续走公共包或 re-export，不扩大本地镜像范围

## 表单与选择器

- 输入、选择、布尔开关、日期等场景优先使用语义正确的公共组件
- 日期、时间、日期范围优先使用 `DatePicker`、`Calendar` 或公共等价组件
- 枚举选择优先使用 `Select` 或 `Combobox`
- 布尔值优先使用 `Switch`、`Checkbox` 或 `RadioGroup`
- 不要用原生 `<input type="date">`、`<input type="time">` 绕过公共组件，除非用户明确要求或公共组件确实缺失

## 浮层与菜单

- `Select`、`Combobox`、`DropdownMenu`、`Popover`、`Tooltip`、`Dialog`、`Sheet`、`Drawer` 修改时，检查定位、层级、滚动和碰撞翻转
- `Dialog`、`Sheet`、`Drawer` 默认只保留必要标题，不主动添加副标题、说明文案、顶部信息条或提示标签；除非用户明确要求保留或补充
- 常规下拉面板应默认在触发器下方展开，并与触发器保持明确间距
- 不要让面板遮住触发器本身，除非该组件语义就是覆盖式展示
- 修改浮层时，注意 `Portal`、`z-index`、`side`、`align`、`sideOffset`、最大高度和滚动区

## 布局与响应式

- 默认同时覆盖桌面端、平板和移动端
- 窄屏下优先保证主操作、导航、筛选和核心信息可达
- 不要交付依赖横向滚动才能完成主要操作的页面
- 对表格、长表单、密集筛选区，要显式设计移动端降级方案，如堆叠、折叠、抽屉、分页或局部滚动
- 不要把关键操作藏在仅 hover 可触发的交互中

## 样式与视觉

- 样式、token、主题变量优先复用 `<shared-styles>`
- 不要硬编码零散颜色、圆角、阴影和视觉语义
- 保持目标项目既有 shadcn 视觉语言，不新建平行设计系统
- 默认简体中文文案；除非用户明确要求，否则不切到英文
- 默认不生成注释性文案、说明性提示、引导性占位文案；除非用户明确要求保留
- 默认删除或避免新增纯说明性的注释、帮助提示、示例占位和解释性辅助文案
