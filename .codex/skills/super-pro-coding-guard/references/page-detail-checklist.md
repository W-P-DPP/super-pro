# Page Detail Checklist

当任务涉及页面新增、页面改版、布局调整、样式微调、表格区改造、搜索区改造、弹窗/抽屉改造时，完成后读取本文件。

## 容器与间距

- 页面根容器是否沿用项目既有页面宽度、左右留白和上下留白
- 相邻区块之间的垂直间距是否稳定，不出现忽大忽小
- 卡片、搜索区、表格区、详情区内部 padding 是否统一
- 标题、描述、操作区、内容区之间的距离是否清晰且一致
- 表单项之间的行距、列距是否稳定
- 不要为了“看起来满”而额外堆无业务价值的空白或装饰层

## 对齐与栅格

- 同一行中的输入框、筛选器、按钮高度是否一致
- 同层级文本、标签、数值、按钮是否沿同一基线或边缘对齐
- 表格列头与表格内容是否对齐
- 卡片标题、正文、底部操作区是否遵守统一对齐关系
- 窄屏下换行后，布局是否仍然有明确主次，不出现错位拼接感

## 边界与层级

- 页面外层、搜索区、表格区、详情区是否真的需要 `Card`；如果只是普通布局承载，不要为了“像后台页面”而额外套卡片
- 卡片边框、圆角、阴影是否沿用现有 token，不出现局部跳变
- 区块层级是否清晰，不依赖夸张阴影、描边或背景色硬分层
- 浮层、弹窗、下拉是否与页面主层级区分清楚，但不显得像另一套系统
- 不要在相同信息层级重复套卡片、重复描边或重复背景块

## 滚动与可视区

- 页面主滚动区和局部滚动区职责是否明确
- 表格区、抽屉、弹窗的滚动容器是否只在必要处出现
- 不出现双重滚动互相抢焦点
- sticky 区域、底部操作区、分页区不会遮挡正文
- 窄屏下不出现未处理的横向滚动；如果局部必须横向滚动，要确保主操作仍可达

## 密度与可读性

- 信息密度高但不拥挤，低但不空洞
- 文本、标签、辅助信息、按钮之间有足够呼吸感
- 空态、错误态、加载态不会把页面撑散或压扁
- 长文案、长标签、长按钮文本不会把布局挤坏

## 交互细节

- hover、focus、disabled、loading 状态下的尺寸和布局不会抖动
- 展开/收起前后，周围区块间距不会突然跳变
- 弹窗打开后首屏重点内容可见，关闭后焦点和滚动位置合理
- 筛选区和表格区联动后，分页、空态、加载态位置稳定

## 通过标准

满足以下条件，才能认为页面细节验证通过：

- 页面结构与主题一致
- 间距、对齐、边界、滚动没有明显破绽
- 桌面端和移动端都没有“看起来像没收尾”的地方
- 用户第一眼能清楚分辨标题、筛选、主体内容和操作区
