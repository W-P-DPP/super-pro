# Frontend Delivery Flow

当任务涉及页面、组件、布局、样式、主题、路由、表单、浮层、表格、菜单、API 集成、鉴权处理、响应式、前端重构、前端删除或修复前端 bug 时，读取本文件。

## 开始前必须确认

1. `design.md`
2. 目标应用的主题来源；若存在 `theme.css`，优先读取它
3. 目标应用现有页面、组件、路由与 `src/api/modules/*`
4. 真实 shared 接入方式：
   - `@super-pro/shared-ui`
   - `@super-pro/shared-types`
   - `@super-pro/shared-constants`
   - `@super-pro/shared-web`

## 实现顺序

1. 先识别这是页面编排、业务组件、基础组件消费、样式修补还是 API 联动。
2. 先复用现有页面模式和 shared 组件，再决定是否新增本地组件。
3. 页面负责 UI、状态、加载、错误和用户意图。
4. API 请求统一落在 `src/api/modules/*`，页面和纯视觉组件不直接调用裸 `fetch` / `axios`。
5. 类型、DTO、常量、权限码优先从 shared 包消费，不要在页面里重复声明。
6. 如果只是需要快速搭一个新列表页，先看 `references/template-index.md`，优先从 `assets/templates/frontend` 复制 API、搜索区、表格区和权限模板。

## 视觉与交互约束

- 默认简体中文文案
- 默认覆盖桌面端、平板、移动端
- 样式 token、主题变量和公共视觉语义优先复用现有来源
- `Dialog`、`Drawer`、`Popover`、`DropdownMenu`、`Select` 等浮层改动时，要检查定位、层级、滚动和窄屏表现
- 不把关键操作藏在仅 hover 可触发的交互里
- 不交付依赖横向滚动才能完成主要操作的页面

## 权限边界

除非用户明确说明不需要权限校验，否则以下场景默认接权限：

- 页面准入
- 菜单显隐
- 按钮、批量操作、导入导出、状态切换
- 用户信息、角色权限、项目权限等敏感信息展示
- 任何消费受保护 API 的关键交互

接法要求：

- 先判断“能不能进”，再判断“能不能做”
- 优先复用现有 context、hook、shared 权限工具
- 前端显隐只负责体验；若有对应后端接口，必须确认接口级强校验也存在
- `401` 和 `403` 要有明确处理路径
- `401` 表示未登录或登录态失效，可以进入登录态恢复或登录跳转
- `403` 表示已登录但无权限，只做无权限反馈、禁用或拦截，不做登录跳转

## 删除清单

删除前端能力时，同步检查并移除直接相关项：

- 路由入口
- 菜单配置
- 页面文件与业务组件
- `src/api/modules/*` 中的对应请求
- 相关 hook、context、测试、样式引用

## 最小验证

- 跑目标应用最相关的 build
- 如果目标应用有测试脚本，补最相关测试
- 手动检查受影响页面的桌面端、移动端和关键交互
- 涉及权限时，检查有权限、无权限、未登录三条路径
- 重点确认 `403` 不会误触发登录跳转
